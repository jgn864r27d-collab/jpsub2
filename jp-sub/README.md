# 日语实时字幕 JpSub（macOS）

看视频时自动把画面里的日文字幕识别成中文，用一条悬浮字幕显示；同时按影片时间轴记录，自动存成 SRT，方便以后再看不看日语也能懂。

---

## 一、30 秒安装（只需做一次）

1. **装编译工具**（如果已经装过 Xcode 或命令行工具可跳过）
   打开「终端」，粘贴回车：
   ```bash
   xcode-select --install
   ```

2. **双击 `一键构建.command`**
   它会在本目录生成 `dist/JpSub.app` 并自动启动。
   若被系统拦截：在该文件上 **右键 → 打开 → 仍要打开**。

3. **首次启动授权两件事**
   - 弹「屏幕录制」：允许。若没弹，去 `系统设置 → 隐私与安全性 → 屏幕录制` 勾选 JpSub，然后重启程序。
   - 弹「控制 QuickTime Player」（只在用 QuickTime 时需要）：允许。路径 `系统设置 → 隐私与安全性 → 自动化`。

4. 屏幕右上角菜单栏出现一个「气泡」图标 → 安装完成。
   `dist/JpSub.app` 可以拖进「应用程序」文件夹长期使用。

> 构建只需一次。以后直接双击 JpSub.app 即可。

## 二、三种用法

### 用法 A：跟 QuickTime Player 一起用（推荐，「插件式」体验）

macOS 的 QuickTime 早已停用第三方插件机制（QTKit 插件体系已废弃），系统不允许往 QuickTime 里塞插件。所以这里用**等效方式**做集成：

| 能力 | 表现 |
| --- | --- |
| 自动贴合画面 | 自动找到 QuickTime 播放窗口，按窗口底部字幕区取帧；窗口移动、缩放、全屏都会自动跟随 |
| 播放联动 | QuickTime 播放 → 自动开始识别；暂停 → 自动停止（省电） |
| 时间轴对齐 | 从播放器读取当前播放进度，字幕时间码与影片严格对齐 |
| 自动归档 | 每句字幕边识别边写入视频同目录的 `视频名.zh.srt`；停止时再补一份 `视频名.zh.txt`（中日对照） |
| 换片自动切换 | 在 QuickTime 里打开另一个视频，自动保存上一份、开始记录新的 |

使用步骤：用 QuickTime 打开视频并点播放 → JpSub 自动接管，不需要任何操作。

> 字幕条默认覆盖在原日文字幕的位置，看起来就像"字幕被换成中文"。想挪位置：鼠标拖动它；想调大小：鼠标滚轮。

### 用法 B：手动框选（浏览器、IINA、VLC、B 站网页版等任意播放器）

点菜单栏图标 → **重新框选字幕区域…** → 在画面上拖一个框 → 松手确认。
框选后会自动关闭「QuickTime 跟随」，避免被窗口位置覆盖。

### 用法 C：直接读取视频文件，批量生成字幕（不用看，放着跑就行）

点菜单 → **打开视频，生成字幕文件…** → 选视频 → 等进度条走完。

- 程序会**自动扫帧**找画面底部的日文字幕，逐句识别并翻译，直接产出：
  ```
  视频名.zh.srt     ← 中文 SRT（时间码与视频对齐）
  视频名.zh.txt     ← 中日对照台词稿
  ```
- 全程离线（抽帧、识别、系统翻译都在本机），不需要播放、不需要开着视频窗口。
- 有进度条和「取消」按钮；处理期间会暂停实时识别，完成后自动恢复。

**它怎么避免“把每个画面都识别一遍”**：先对字幕区做快速“画面变化检测”——字幕没变的帧直接跳过，只在字幕出现/消失的那一刻才做 OCR，因此几百句字幕的视频只需真正识别几百次，而不是几万次。

**识别范围怎么调**：默认取画面**底部 25%**（内嵌硬字幕通常在这里）。如果字幕位置偏高/偏低，在菜单里改「视频字幕区域高度」（15% / 22% / 25% / 30% / 40%）。

**支持的格式**：AVFoundation 能解码的都在范围内（mp4 / mov / m4v / ts / mpg 等）；mkv 视 macOS 版本而定，部分可识别。若提示“无法读取”，先用 QuickTime 或格式转换工具转成 mp4 再喂给它。

**关于耗时**：一部 2 小时的视频，抽帧约几分钟，OCR 只在字幕变化时发生，翻译约几百句；整体通常十几分钟量级，取决于字幕句数和视频分辨率。

## 三、字幕文件

保存位置：**视频文件所在目录**（和视频同名）

```
影片名.mov
影片名.zh.srt      ← 中文 SRT（标准字幕格式）
影片名.zh.txt      ← 中日对照文本（阅读/整理用）
```

SRT 示例：

```
1
00:00:12,480 --> 00:00:15,020
你根本什么都不明白。

2
00:00:15,180 --> 00:00:17,900
我早就知道这件事了。
```

**以后再看的三种方式**
- 用 **IINA / VLC** 打开同一视频，会自动加载同目录同名 `.srt`；
- 用 QuickTime 打开视频 → 把 `.srt` 拖到字幕菜单（部分版本可用）；更稳的是转成 `.mov` 内嵌字幕轨道；
- 直接把 `.zh.txt` 当台词稿阅读。

菜单里还有：**保存字幕…**（手动导出到指定位置）、**清空字幕记录**。

## 四、菜单栏功能一览

| 菜单项 | 作用 |
| --- | --- |
| 状态 / 引擎 / QuickTime 状态 / 已记录句数 | 当前运行情况 |
| 暂停识别 / 开始识别 | 手动开关 |
| 重新框选字幕区域… | 自定义识别区域（会关闭跟随） |
| 恢复默认字幕区域 | 回到主屏底部默认区域 |
| 显示日文原文 | 中文上方加一行小字日文 |
| 字号 / 字幕背景 | 也可用鼠标滚轮、拖动字幕条 |
| 刷新间隔 | 0.5–1.4 秒，越小越跟手、越费 CPU |
| **QuickTime 跟随播放器** | 开关自动贴合 QuickTime |
| QuickTime 字幕区域高度 | 15% / 22% / 30% / 38%，字幕位置偏上时可调大 |
| QuickTime 暂停时停止识别 | 默认开 |
| 自动保存字幕（视频同名 .srt） | 默认开，每 8 句落盘一次，停止时补写 |
| **打开视频，生成字幕文件…** | 直接读视频批量出 SRT，不用播放 |
| 视频字幕区域高度 | 15%–40%，字幕位置不对时调 |
| 视频抽帧间隔 | 0.3 / 0.5 / 1.0 秒/帧，越小越不丢短字幕、越慢 |
| 翻译引擎 | 见下 |
| API 设置（OpenAI 兼容） | 填 DeepSeek / OpenAI / Moonshot 的 Base URL、Key、模型名 |

## 五、翻译引擎怎么选

| 引擎 | 特点 | 适合 |
| --- | --- | --- |
| **Apple 系统翻译（默认）** | 完全离线、免费、无 Key、延迟最低 | 日常首选 |
| MyMemory 免费在线 | 无需 Key，质量一般，有频率限制 | 系统语言包没装好时的兜底 |
| Google 免费接口 | 质量较好 | 能正常访问 Google 的网络环境 |
| OpenAI 兼容 API | 质量最好、可指定术语风格 | 有 Key 且追求质量（如 DeepSeek） |

**关于系统语言包**：Apple 翻译的日语↔中文语言包需要下载一次。第一次翻译时系统会弹窗请求下载，同意即可，之后完全离线。
若一直不弹或翻译失败，App 会自动回退到在线引擎，不影响使用；也可以去 `系统设置 → 通用 → 语言与地区 → 翻译语言` 手动下载日语。

## 六、常见问题

**1. 字幕条一直是空的**
99% 是屏幕录制权限没给。菜单 → 屏幕录制权限设置，勾选 JpSub 后**重启程序**。

**2. QuickTime 打开视频但字幕条没反应**
看菜单第三行是否显示「QuickTime：播放中」。
若是「未打开视频」：确认 QuickTime 里确实有视频窗口；点菜单 → 自动化权限设置，允许 JpSub 控制 QuickTime。

**3. 字幕比画面慢半拍**
正常。链路是：截帧（0.05s）→ OCR（0.15s）→ 翻译（0.15s）+ 轮询间隔（0.7s），整体约 1 秒。
想更快：刷新间隔调 0.5 秒；或把框选区域收紧，减少 OCR 面积。

**4. 有些句子识别不出来**
- 框选区域要只包含字幕，不要带台标、进度条；
- 字幕字号太小时识别率下降，把框选拉紧一点反而更准；
- 复杂背景上的艺术字字幕（描边/竖排）识别率有限。

**5. 翻译出来是日文原文**
说明当前引擎都失败了（系统语言包未授权 + 在线不可达）。切换引擎试试。

**6. 保存字幕失败**
视频目录不可写（比如在只读磁盘镜像、网络盘里）。用菜单 **保存字幕…** 手动选目录。

**7. 副屏 / 双屏能用吗**
可以。手动框选支持任意屏幕；QuickTime 跟随会识别 QuickTime 窗口所在的那块屏。

**8. 会不会上传我的画面**
不会。截帧、OCR、系统翻译全部在本机完成；只有当你主动选择「Google / MyMemory / OpenAI」在线引擎时，才会把**识别出的文字**（不是画面）发给对应服务。

**9. 视频生成字幕漏句 / 识别不到**
- 字幕位置不对：调「视频字幕区域高度」；
- 短字幕（<0.5 秒）被跳过：把「视频抽帧间隔」调到 0.3；
- 字幕是描边艺术字/竖排/透明底：识别率会下降，属于 Vision OCR 的固有限制；
- 画面底部有动态水印/滚动弹幕：会干扰识别，尽量用干净的片源。

## 七、技术实现（给你自己和后续维护看）

```
屏幕区域 ──screencapture -R──► CGImage
                                   │
                         Vision OCR（ja-JP，离线）
                                   │ 逐行合并 + 相似句去重
                         TextUtils.normalize / similar
                                   │
              ┌────────────────────┴────────────────────┐
        Apple Translation（离线）              在线引擎兜底
        macOS 15+，无 Key                      MyMemory / Google / OpenAI
              └────────────────────┬────────────────────┘
                                   │
                  ┌────────────────┴───────────────┐
            悬浮字幕条（NSPanel）           SubtitleRecorder
            置顶/可拖/滚轮调字号            → 视频同名 .zh.srt / .zh.txt
```

| 模块 | 文件 | 说明 |
| --- | --- | --- |
| 取帧 | `Sources/Capture.swift` | 走系统 `screencapture` 命令行，避开 ScreenCaptureKit 各版本 API 差异 |
| OCR | `Sources/OCR.swift` | Vision `VNRecognizeTextRequest`，按视觉顺序重组行 |
| 离线翻译 | `Sources/AppleBridge.swift` | `Translation` 框架 + `translationTask` 长驻 session |
| 在线翻译 | `Sources/Translators.swift` | MyMemory / Google / OpenAI 兼容，自动回退 |
| QuickTime 联动 | `Sources/QuickTime.swift` | AppleScript 读播放状态/进度/文件；CGWindowList 读窗口位置 |
| 字幕归档 | `Sources/Recorder.swift` | 时间轴合并、SRT 生成、节流写盘 |
| 悬浮窗 | `Sources/Panel.swift` | borderless NSPanel，`screenSaver` 层，全屏可见 |
| 框选 | `Sources/RegionSelector.swift` | 多屏覆盖 + 拖拽选区 |
| 主循环 | `Sources/Pipeline.swift` | 0.7s 节拍，异步取帧/识别/翻译 |
| 视频批处理 | `Sources/VideoProcessor.swift` | AVFoundation 抽帧 + 变化检测跳过重复 OCR + 批量翻译 |

**重新构建**：改完源码后再次双击 `一键构建.command`。
**重置所有设置**：`defaults delete com.local.jpsub`

---

## 八、卸载

1. 退出 JpSub（菜单 → 退出）
2. 删除 `JpSub.app`
3. 清理：`defaults delete com.local.jpsub`
4. 到 `系统设置 → 隐私与安全性` 里移除 JpSub 的屏幕录制/自动化授权
